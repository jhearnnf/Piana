# 🎹 Piana

A cute, minimal **Synthesia-style piano trainer** for the desktop. Load a MIDI song, watch
the notes fall onto an on-screen keyboard, play along on a real USB MIDI keyboard, and get
scored on accuracy, timing and mistakes.

## Install it

Piana runs on **Windows and macOS**. Both start the same way:

```bash
npm install
npm run build      # the app the desktop shell runs
npm run icon       # the icon images, once
```

**Windows**

```bash
npm run shortcut   # Desktop + Start Menu shortcuts
```

Then launch **Piana** from the Desktop like any other app.

> `npm install` and Electron upgrades both wipe `Piana.exe`. Re-run `npm run shortcut` (or
> just `npm run exe`) to put it back.

**macOS**

```bash
npm run mac                    # builds Piana.app next to Electron
npm run mac -- /Applications   # …or straight into Applications
```

Then drag **Piana.app** to the Dock.

> A copy in `node_modules` is wiped by `npm install` and Electron upgrades — re-run
> `npm run mac`. One in `/Applications` survives both.

Either way the launcher runs *this folder* rather than a packaged copy, so after changing
the source a `npm run build` is all it takes. And if you'd rather not install anything at
all, `npm run app` builds and opens the window directly on both.

## Use it

Click **Load MIDI…** (or press <kbd>Ctrl</kbd>/<kbd>⌘</kbd>+<kbd>O</kbd>, or drop a `.mid`
onto the window) to open a song, or **Load demo** for the built-in Twinkle Twinkle. The dialog opens
in whichever folder you last took a song from — your Music folder until then. The song
starts as soon as it loads; with Wait mode on it comes to rest on the first note and holds
there until you play it.

No MIDI keyboard? You can also play with your **computer keys** (A–L, `Z`/`X` to change
octave) or by **clicking the on-screen piano** — handy for trying things out.

- **Difficulty** — Easy / Medium / Hard. Generated by simplifying the real MIDI (thinning
  chords), so every level stays physically playable with normal-size hands.
- **Hand** — practise Left, Right, or Both. The app plays the other hand for you.
- **🎼 Tracks** — which hand plays each track of the file. A two-track file is trusted as
  written (lower track = left hand); anything else is handed to **Auto split**, which works
  the hands out from the notes: it follows where each hand actually is, so it copes with a
  melody that crosses under, a bass that climbs into the treble, and single-track files that
  never separated the hands at all. Set any track to Auto split, Left hand or Right hand —
  the falling notes recolour to match.
- **Sections** — the song is auto-split at natural rests so you can drill one part. Turn on
  **Loop** to repeat a section.
- **Wait mode** — playback waits until you hit the right note. **On by default**, since
  that's how you learn a piece you can't yet play; switch it off and the setting sticks.
- **Speed** — slow it down to 0.5× or 0.75×.
- **🔊 / 🔇** — mute everything the app plays: the accompaniment *and* the echo of your own
  presses. Handy when your MIDI keyboard already makes its own sound. The notes still fall
  and you're still scored. Remembered between launches.
- **Keys** — how much of the piano is on screen. **Auto** (the default) trims it to the
  octaves the song actually uses, so the keys are as wide as they can be; **Full 88** shows
  the whole piano. Your choice is remembered between launches.
- **Scoring** — accuracy, perfect/good/missed, wrong notes, max combo, timing and a star
  rating. Best scores are saved per song + difficulty + hand + section.
- **🏆 Scores** — every best you've set, grouped by song, best run first. Playback pauses
  while it's open. "Clear all" wipes them (it asks once first).

## How it's built

- **Vite + TypeScript**, no UI framework — the piano and falling notes are drawn on a
  `<canvas>` for smooth animation.
- Pure, unit-tested logic (parsing, hand-split, difficulty, sections, scoring, clock, zoom)
  is kept separate from rendering and device I/O.
- A song is always a normalized `Song` model, so the *source* can change later (online MIDI
  search, or audio→MIDI) without touching the rest of the app.

### The desktop shell

`electron/` is a thin wrapper — the app is the same web code, and it still runs in a browser
tab with `npm run dev`. The shell only adds what a tab cannot do:

- **Serves the build over a `piana://` scheme** rather than `file://`
  (`electron/serve.cjs`). `file://` gives the page an opaque origin, which blocks the
  `fetch` that "Load demo" needs, and leaves the secure context Web MIDI wants ambiguous.
- **Grants Web MIDI**, and refuses every other permission. Electron denies MIDI by default,
  which the app reports as "MIDI: blocked".
- **Remembers the window** across launches, including which monitor
  (`electron/window-state.cjs`).
- **Opens `.mid` files** from the File menu, <kbd>Ctrl</kbd>/<kbd>⌘</kbd>+<kbd>O</kbd>, a
  drop onto the window, or the command line — a path handed to an already-open Piana goes
  to that window rather than starting a second one. On macOS the same is true of Finder's
  *Open With* and a drop onto the Dock tile, which the bundle declares itself a handler for.
  Wherever a song came from is recorded in `prefs.json` so the next dialog starts there
  (`electron/prefs.cjs`).

`window.piana` is the whole bridge (`electron/preload.cjs`): a native file picker and an
"here is a song" event. It is absent in the browser build and the renderer treats it as
optional, so neither way of running the app is the second-class one.

The two platforms differ only where they have to, and `electron/menu.cjs` is where most of
it is: macOS routes <kbd>⌘Q</kbd>, <kbd>⌘W</kbd> and the clipboard *through the menu bar*,
so it gets app, Edit and Window menus that Windows has no use for, and loses the `&`
mnemonics that mean nothing there. It is a pure function of the platform, so `npm test`
checks the macOS menu from any machine. Elsewhere: closing the last window quits on Windows
but not on macOS, where an app with no windows is normal and the Dock icon brings it back.

There is no packaging step and no `electron-builder` on either platform — both launchers run
this source tree, so a rebuild is live immediately.

- `tools/make-exe.ps1` copies `electron.exe` and rewrites its icon resources in place —
  Windows takes a taskbar icon from the running executable and ignores both the window icon
  and the shortcut's, so this is the only thing that actually changes it.
- `tools/make-app.sh` copies `Electron.app`, renames its executable, rewrites the
  `Info.plist` keys that name an app, and leaves a three-line pointer at this checkout in
  `Contents/Resources/app`. Same reason: the Dock takes its icon and its name from the
  bundle it launched, and nothing an already-running app does will change them.

Both copies stay in `node_modules/electron/dist`, where the libraries they need already are.
Neither needs anything installed beyond the OS — PowerShell's resource APIs on one side,
`ditto`/`PlistBuddy`/`iconutil`/`codesign` on the other.

## A note on songs & copyright

Piana never ships or distributes copyrighted songs — you bring your own MIDI files, like a
media player. If you ever plan to **sell** or publish it, get proper legal advice: MIDI
files of copyrighted songs are protected, and "the user chose the song" is a weak defence.
